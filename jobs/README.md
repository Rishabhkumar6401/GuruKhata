# jobs/

Scheduled jobs, written as plain runnable Node scripts (`DATABASE_URL=... node jobs/generate-dues.js`; run `npm install` here first for `pg`). Later each script becomes an AWS Lambda function: we wrap its body in an exported `handler` (the script code moves into a function instead of running at import), deploy it alongside the API, and point an **EventBridge cron rule** at it — `cron(30 18 L * ? *)`-style schedules (UTC) give us "1st of month, midnight IST" for dues generation and "daily 8:00 am IST" for the dues-today push, both inside the free tier. `DATABASE_URL` then comes from the Lambda environment instead of the shell, which is why these scripts read `process.env` directly and use no dotenv. Every job must stay idempotent (`ON CONFLICT DO NOTHING` or equivalent) because EventBridge can retry or double-deliver.

`generate-dues.js` backfills: it creates every missing month up to the current IST month for active students with a fee above ₹0 (from the later of the student's created month and the month after their latest due, capped at 12 months back). The rule and its SQL live in `api/src/lib/dues-generation.js`, shared with the API's lazy generation, so the job imports `../api/src/lib/` — include that dependency-free module (and its `time.js`) when packaging the job as its own Lambda.
